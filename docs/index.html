psychosis-guard

AI safety shouldn't reset every turn.

Trajectory-aware safety middleware for long-running LLM conversations. Open source, Apache 2.0, Python 3.10+.
Namwoo Jang

GitHub PyPI Docs psychosis-bench 한국어

A chatbot can validate a user's delusional belief a little more on every turn while no single message ever trips a content filter. Conventional guardrails inspect one message at a time; the harm here is cumulative.

psychosis-guard tracks the whole conversation, scores where it is heading, and steps in with a graduated intervention before that drift compounds. It runs as an OpenAI-compatible HTTP proxy in front of any chatbot, as a Python library, or in a check-only mode over replies your application already has. Without an API key, the whole pipeline runs on deterministic mocks.

How it works

Every user turn passes through five rail stages. Stages 1–3 and 5 mirror the input, dialog, output and action rails of NVIDIA NeMo Guardrails. Stage 4 is new: it carries state across the conversation.

  • Input rail. Pre-response risk estimate from the user turn plus the prior trajectory slope. HIGH short-circuits the chatbot.
  • Dialog rail. Mode A injects a graduated system prompt into the chatbot call.
  • Output rail. A judge scores the reply: reinforcement, sycophancy, pushback, escalation, help-referral.
  • Trajectory rail. Folds the turn into cumulative state and computes the least-squares slope of delusion density over the conversation.
  • Action rail. Composite risk becomes NONE, LOW, MEDIUM or HIGH. Mode B rewrites the reply.
risk = Σ wᵢ · signalᵢ + slope_boost · max(slope, 0)

Only an escalating trajectory raises risk; a falling slope is not rewarded, so interventions do not switch off while density is still high. The intervention is graduated rather than binary: a grounding question at LOW, an honest alternative explanation at MEDIUM, de-escalation and referral at HIGH. Thresholds and weights live in YAML.

Results

Measured on psychosis-bench (Dohnány et al., 2025): 16 scripted 12-turn conversations that progress from loneliness to a delusional belief to a harmful act, scored with the benchmark's own LLM-judge rubric. DCS is delusion confirmation (0–2, lower is better), HES harm enablement (0–2, lower is better), SIS whether a safety intervention was offered (0–1, higher is better). Same chatbot (gpt-4o-mini), judge and script for every row. n = 16, one repetition, mean ± 95% CI.

  • Against the unguarded chatbot, mode B and combined improve all three metrics (paired Wilcoxon, Holm-corrected, d = 0.8–2.1, p < .02) and eliminate every full-validation and full-compliance turn.
  • Against the identical pipeline with the trajectory rail off, the rail alone accounts for DCS −0.16, HES −0.33, SIS +0.69 (p < .05).
  • The middleware is statistically indistinguishable from a one-paragraph safety system prompt, obtained without access to the chatbot's prompt. Stacking the two is the best row on every metric.
  • 0 interventions in 520 turns of benign control conversations.

What this does not show. These are scores on the chatbot's replies to a fixed script. In a separate reactive simulation, where an LLM-played user adjusts the next message to the reply, the simulated user's delusion density and conviction do not improve, and the interventions that insert the most safety language make that user worse. The simulator is unvalidated and the judge is an LLM checked only against another LLM (κ ≈ 0.5). Treat the table as a bot-side benchmark, not evidence of user outcomes.

Get started

pip install "psychosis-guard[server,openai,anthropic]"
from psychosis_guard import PsychosisGuard

guard = PsychosisGuard.from_config("config.yml")   # mocks, no API key
reply = guard.send("Lately I keep noticing patterns that feel like signals meant for me.")
guard.log[-1].level.name                            # NONE | LOW | MEDIUM | HIGH
psychosis-guard serve    # OpenAI-compatible proxy on :8080

Point any OpenAI SDK at http://localhost:8080/v1; the reply carries an X-Guard-Level header. See the HTTP API, configuration and architecture docs.

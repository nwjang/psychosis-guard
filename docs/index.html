AI safety shouldn't
reset every turn.

psychosis-guard is trajectory-aware safety middleware for LLM chatbots. It watches the whole conversation, not one message, and steps in before slow drift toward a delusional belief compounds.

Get started View on GitHub

No single turn crosses a content filter. The conversation still ends somewhere it shouldn't. psychosis-guard fits a slope over the whole exchange and escalates a graduated response as it climbs. Illustrative values.

Why

One message at a time
isn't enough.

A chatbot can validate a delusional belief a little more on every turn while every individual reply looks harmless. Turn-local guardrails were never built to see that.

How it works

Five rails. One of them remembers.

Every user turn passes through five stages. Four mirror the input, dialog, output and action rails of NVIDIA NeMo Guardrails. The fifth is new: it carries state across the conversation.

Stage 1

Input Rail

Pre-response risk estimate from the user turn plus the prior trajectory slope. HIGH short-circuits the chatbot and returns a safe response.

Stage 2

Dialog Rail

Mode A injects a graduated system prompt into the chatbot call.

Stage 3

Output Rail

A judge scores the reply: reinforcement, sycophancy, pushback, escalation, help-referral.

Stage 4 · New

Trajectory Rail

Folds the turn into cumulative state and computes the least-squares slope of delusion density over the conversation. Only an escalating trajectory raises risk; a falling slope is never rewarded, so interventions don't switch off while density is still high.

risk = Σ wᵢ · signalᵢ + slope_boost · max(slope, 0)
Stage 5

Action Rail

Composite risk becomes a level: NONE, LOW, MEDIUM or HIGH. Mode B rewrites the reply to match. Thresholds and weights live in YAML, outside the code.

Low. Ground.

A grounding question that invites the user to check the belief against something concrete.

Medium. Explain.

An honest alternative explanation, offered without dismissing the user.

High. De-escalate and refer.

De-escalation and a referral to human support. Can fire before the chatbot is even called.

Better than unguarded on every metric.

B and combined improve DCS, HES and SIS (paired Wilcoxon, Holm-corrected, d = 0.8–2.1, all p < .02) and eliminate every full-validation and full-compliance turn.

The rail is what does it.

Against the identical pipeline with the Trajectory Rail off, the rail alone accounts for DCS −0.16, HES −0.33, SIS +0.69 (all p < .05). Turn-local scoring under-calls a slowly escalating script.

Parity with a safety prompt, no prompt access needed.

Statistically indistinguishable from a one-paragraph safety system prompt. Stacked together, the best row on every metric.

Quiet when nothing is wrong.

0 interventions across 520 turns of benign control conversations.

What this does not show

These are scores on the chatbot's replies to a fixed script. In a separate reactive simulation, where an LLM-played user adjusts the next message to the reply, referral and pushback rates rise just as here, but the simulated user's delusion density and conviction do not improve, and the interventions that insert the most safety language make that simulated user worse.

That simulator is unvalidated and the judge is an LLM checked only against another LLM (κ ≈ 0.5). Treat the table as a bot-side benchmark, not evidence of user outcomes. Three repetitions and human judge labels are the planned next step.

Compatibility

Works with what you already run.

Any chatbot behind a single respond() interface, or replies your application already has. Judge and rewriter can be a different, cheaper model.

OpenAIAnthropicOllamavLLMLM StudioGroqOpenRouterAny OpenAI-compatible serverYour own bot

Drop-in proxy

Point any OpenAI SDK at /v1/chat/completions. Nothing else changes. Without a session id the proxy is stateless and scales horizontally.

Guarded turn

POST /v1/guard/turn. The middleware calls the upstream chatbot for you and returns the reply with its risk assessment.

Check-only

POST /v1/guard/check. Bring a reply from any chatbot; it is scored and, if needed, rewritten. Fully model-agnostic.

Get started

Guarded in three lines.

Runs on deterministic mocks with no API key. Add a provider when you're ready.

$ pip install "psychosis-guard[server,openai,anthropic]"
Python
from psychosis_guard import PsychosisGuard

guard = PsychosisGuard.from_config("config.yml")
reply = guard.send("Lately I keep noticing patterns "
                   "that feel like signals meant for me.")

guard.log[-1].level.name        # NONE | LOW | MEDIUM | HIGH
guard.summary()["delusion_slope"]
OpenAI SDK, through the proxy
psychosis-guard serve      # :8080

from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1",
                api_key="anything")
raw = client.chat.completions.with_raw_response.create(
    model="guarded", messages=history,
    extra_headers={"X-Session-Id": session_id})
raw.headers["X-Guard-Level"]
